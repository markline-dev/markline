## Callouts

<Note>A neutral note.</Note>
<Info>The same as a note, by another name.</Info>
<Tip title="Tip">A helpful suggestion.</Tip>
<Warning>Something to watch out for.</Warning>
<Danger>A destructive or irreversible action.</Danger>
<Check>A confirmation of success.</Check>

Each takes an optional `title`, shown in bold before the text.
`<Callout tone="info|ok|warn" title="…">` is the same box with the tone
chosen by a prop, which helps when converting docs from another tool.

Each also takes an `icon` in place of its own: a
[Phosphor](https://phosphoricons.com) icon name, as `<Card>` takes it, or one
or two characters such as `↗` or an emoji. Text icons are symbols or emoji:
letters, such as `A` or `OK`, are read as an icon name. It's shown in the
callout's colour. Paths and URLs aren't accepted, so a callout never loads an image.

```mdx
<Callout title="Migrating from OpenAI?" icon="↗">
  Point your SDK at our endpoint and swap the key.
</Callout>
<Tip icon="rocket-launch">Ship it.</Tip>
```

`<MigrationCallout>` is deprecated, and will be removed in a later release;
use `<Callout title="…" icon="…">` as above.

## Cards

<CardGroup cols={2}>
  <Card title="Quickstart" icon="rocket-launch" href="/quickstart">Link cards group neatly.</Card>
  <Card title="CLI" icon="terminal-window" href="/cli">Use them for navigation.</Card>
</CardGroup>

`icon` takes a [Phosphor](https://phosphoricons.com) icon name, like sidebar
icons do. An emoji works too.

```mdx
<Card title="Quickstart" icon="rocket-launch" href="/quickstart">…</Card>
```

`variant="tile"` puts the icon in a tinted square above the title, for a
help-center home. Set it on a `<CardGroup>` to style every card in the grid:

<CardGroup cols={2} variant="tile">
  <Card title="Get started" icon="rocket-launch" href="/quickstart">Set up a project and publish your first page.</Card>
  <Card title="Components" icon="squares-four" href="/components">Everything you can use in a page.</Card>
</CardGroup>

```mdx
<CardGroup cols={3} variant="tile">
  <Card title="Get started" icon="rocket-launch" href="/quickstart">…</Card>
</CardGroup>
```

## Images

Markdown images shrink to fit the text column, with a thin frame. Click one
that was shrunk to see it full size.

```mdx
![The Test panel](/shots/test.png "The Test panel, open beside a draft")
```

The title in quotes shows as a caption. For screenshots that should follow
the reader's theme, add both and mark them with `#light` and `#dark`; each
shows only in its theme:

```mdx
![Inbox](/shots/inbox.png#light)
![Inbox](/shots/inbox-dark.png#dark)
```

`#nozoom` turns off click-to-zoom for one image. `<Image>` does all of it
in one tag:

```mdx
<Image src="/shots/inbox.png" dark="/shots/inbox-dark.png" alt="Inbox" caption="The Inbox" zoom={false} />
```

## Menu paths

A route through your product's menus, with each step bold and a chevron
between them (read aloud as "then"):

```mdx
Go to <MenuPath>Settings > API keys > New key</MenuPath>.
```

Bold text with ` → ` or ` › ` in it becomes one automatically, so
`**Teach → Playbooks**` renders as <MenuPath>Teach > Playbooks</MenuPath>.

## Video

```mdx
<Video src="https://www.youtube.com/watch?v=…" title="Introduction" />
<Video src="/videos/setup.mp4" poster="/videos/setup.jpg" caption="Setting up a workspace" />
```

`src` can be a video file (`.mp4`, `.webm`), played in the browser's own
player, or a YouTube, Vimeo, Loom or Wistia link, which is turned into that
provider's embed. YouTube links use its no-cookie domain, and a `?t=` start
time carries over. Videos fill the column at 16:9, and embeds load when they
scroll into view.

| Prop | |
| --- | --- |
| `src` | A file path or URL, or a video page link |
| `title` | Names the video for screen readers |
| `poster` | Image shown before a video file plays |
| `caption` | Text under the video |

## Audio

A player for voice samples and recorded calls: play and pause, a seek bar
with the elapsed and total time, 15-second skips, playback speed and mute.

```mdx
<Audio src="/samples/greeting.mp3" title="Front desk voice" caption="A sample greeting" />
```

`<AudioGroup>` sets players side by side, for a before and after:

```mdx
<AudioGroup>
  <Audio src="/samples/noisy.mp3" title="Original audio" />
  <Audio src="/samples/clean.mp3" title="Isolated audio" />
</AudioGroup>
```

`src` is a file in `public/` or a URL, in any format the browser plays (MP3,
M4A, WAV, Ogg). Starting one player pauses any other on the page. On phones
a group stacks. `--audio-accent` in `theme.cssVariables` colours the play
button and progress (default: the text colour).

## Link lists

Rows of links with a title, an optional description and an icon. Use them
for collection pages and "see also" lists. The "Related articles" list at the
end of a page uses the same component.

<LinkList>
  <LinkItem href="/quickstart" title="Quickstart" description="Create a docs site in under a minute." />
  <LinkItem href="/templates" title="Templates" meta="4 built in" description="Start from a ready-made look." icon="palette" />
</LinkList>

```mdx
<LinkList>
  <LinkItem href="/quickstart" title="Quickstart" description="Create a docs site in under a minute." />
  <LinkItem href="/templates" title="Templates" meta="4 built in" description="Start from a ready-made look." icon="palette" />
</LinkList>
```

`meta` shows in the accent colour before the description. `icon` takes a
[Phosphor](https://phosphoricons.com) name in place of the page icon, or
`"none"`.

## Steps

<Steps>
  <Step title="First">Describe the first action.</Step>
  <Step title="Then">Describe the next one.</Step>
</Steps>

`<Steps toc>` lists the step titles in "On this page", so readers can jump to
step 4 of a long recipe. For every `<Steps>` on a page, set `toc: steps` in
its frontmatter instead. Each step is listed under the `##` heading before it.

## Code groups

The same snippet in several languages, as tabs. Write plain fenced code
blocks inside `<CodeGroup>`; each tab is named by the fence's `title`, or a
bare label after the language (` ```bash cURL `), or else the language.

<CodeGroup>
```python
import markline
```
```ts title="TypeScript"
import { markline } from "markline";
```
```bash cURL
curl https://example.com
```
</CodeGroup>

A reader's pick carries over: every group with the same tab labels switches
with it, on this page and later ones (it's kept in the browser's
`localStorage`). `sync="name"` joins groups with different labels on one
channel (each switches when it has the picked tab); `sync={false}` keeps a
group to itself.

## Param fields

<ParamField path="id" type="string" required>The unique identifier.</ParamField>
<ParamField query="limit" type="integer" default={20}>Maximum number of results.</ParamField>

`<ResponseField>` takes the same props as `<ParamField>` and looks the same.
Use it for the fields of a response, so the source reads clearly. Either one
takes `path`, `query`, `header`, `body` or `name` as its label, plus `type`,
`required` and `default`.

## Paths

Numbered cards that link to the next pages to read, such as the routes
through a getting-started section. `arrow` is the text in the card's corner.

<Paths>
  <Path num={1} href="/quickstart" title="Quickstart" arrow="Start →">Create and run a site.</Path>
  <Path num={2} href="/configuration" title="Configure" arrow="Next →">Set up navigation and branding.</Path>
</Paths>

```mdx
<Paths>
  <Path num={1} href="/quickstart" title="Quickstart" arrow="Start →">Create and run a site.</Path>
  <Path num={2} href="/configuration" title="Configure" arrow="Next →">Set up navigation and branding.</Path>
</Paths>
```

## Endpoint lists

`<EndpointList />` lists every operation in your OpenAPI spec, grouped by tag,
each linking to that operation's page in your API reference
(`/api-reference/<operationId>`). Put it in a
hand-written API introduction. `tags` limits it to some tags, by their names in
the spec:

```mdx
<EndpointList tags={["users", "billing"]} />
```

## Code blocks from data

For code written as fenced blocks, use a [code group](#code-groups).
`<CodeBlock>` takes the snippets as a prop instead. Each snippet is a tab,
named by its `label` or else its `lang`:

```mdx
<CodeBlock
  snippets={[
    { lang: "bash", label: "cURL", code: "curl https://api.example.com/v1/users" },
    { lang: "js", label: "Node", code: "await client.users.list();" },
  ]}
/>
```

## GitHub stars

`<GitHubStars repo="owner/name" />` shows a repo's star count, such as
"★ 1.2k", as a link to the repo. It shows nothing until there's a count. The
build fetches the counts of the repos your pages name (up to 20), and
[`topbar.githubStars`](/configuration) decides whether readers' browsers
refresh them. With `"live"`, each repo shown is its own request from the
reader's browser, at most hourly, so a page naming many repos makes many:

```mdx
Markline is open source <GitHubStars repo="markline-dev/markline" />.
```
