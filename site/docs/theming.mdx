Everything visual is driven by the `theme` block (and a couple of `topbar`
fields) in your config — no component overrides required.

## The config file

Markline reads **`markline.json`**, falling back to **`docs.json`** so projects
migrating from a `docs.json` config work unchanged.

<Note>All theming lives under `theme` in that file. Image paths (`logo`,
`favicon`) are served from your project's `public/` directory.</Note>

## Default theme

<ParamField path="theme.appearance" type='"system" | "light" | "dark"'>
  The default color scheme. `"system"` follows the OS (the default); set
  `"dark"` or `"light"` to force one. Visitors can still toggle, and their
  choice is remembered.
</ParamField>

```jsonc
"theme": { "appearance": "dark" }   // open in dark mode by default
```

## Logo & favicon

The logo can be an **icon + wordmark** (the common docs pattern), light/dark
**images**, or just **text**.

<ParamField path="theme.logo.icon" type="string | object">
  Small mark shown next to the name (e.g. `/logo-mark.svg`), or
  `{ light, dark }` for a version per theme.
</ParamField>
<ParamField path="theme.logo.iconTile" type="boolean">
  For a single dark mark: puts it on a rounded tile in the text colour, dark
  in light mode (with the mark inverted to white) and light in dark mode, so
  it shows in both themes.
</ParamField>
<ParamField path="theme.logo.text" type="string">Wordmark text shown beside the icon (defaults to `name`).</ParamField>
<ParamField path="theme.logo.light / theme.logo.dark" type="string">Full logo images, swapped by color scheme. Used when no `icon` is set.</ParamField>
<ParamField path="theme.favicon" type="string">Favicon path, e.g. `/favicon.svg`.</ParamField>

```jsonc
"theme": {
  "logo": { "icon": "/logo-mark.svg", "text": "acme" },
  "favicon": "/favicon.svg"
}
```

## Accent color

<ParamField path="theme.colors.primary" type="string">Brand accent (hex) for light mode.</ParamField>
<ParamField path="theme.colors.primaryDark" type="string">Brand accent for dark mode (and hover).</ParamField>

```jsonc
"theme": { "colors": { "primary": "#4f46e5", "primaryDark": "#818cf8" } }
```

Text on these colours (the primary button, the brand banner) is white, or
near-black when the colour is too light for white to read: below the 3:1
contrast WCAG asks of buttons. A pale green or yellow `primaryDark` gets dark
button text in dark mode without any setting. To choose it yourself:

<ParamField path="theme.colors.primaryText / primaryTextDark" type="string">
  Text colour (hex) on `primary` and, in dark mode, on `primaryDark`.
</ParamField>

## Icons

<ParamField path="theme.iconWeight" type='"thin" | "light" | "regular" | "bold" | "fill" | "duotone"'>
  The [Phosphor](https://phosphoricons.com) weight for every icon (sidebar,
  cards, link lists). Default `regular`. One icon can override it as
  `rocket-launch:duotone`.
</ParamField>

## Full palette

For deeper theming, override any CSS custom property via
`theme.cssVariables`, split into `light` and `dark`. **Color values are
space-separated RGB triples** (e.g. `247 246 241`), not hex.

<Note>Always provide both `light` and `dark` if you customize the palette —
otherwise dark mode falls back to Markline's default dark.</Note>

The tokens you'll reach for most:

| Token | Meaning |
| --- | --- |
| `--c-brand`, `--c-brand-deep` | Accent + hover (also set via `colors`) |
| `--c-on-brand` | Text/icon color on brand surfaces |
| `--c-paper`, `--c-paper-2` | Page and raised surface backgrounds |
| `--c-ink`, `--c-ink-soft`, `--c-ink-2`, `--c-ink-3` | Text shades |
| `--c-slate-0` … `--c-slate-8` | Neutral scale (borders, muted text) |

Component variables take any CSS value (a colour, a length, a shadow),
not triples:

| Variable | What it sets |
| --- | --- |
| `--card-bg`, `--card-radius` | Every `<Card>`'s fill and corner radius |
| `--card-shadow`, `--card-shadow-hover` | Its shadow, at rest and on hover |
| `--card-icon-bg`, `--card-icon-color` | The tile style's icon square, and card icon colour |
| `--brand-tile-bg`, `--brand-tile-size`, `--brand-tile-radius` | The logo tile (`logo.iconTile`) |
| `--brand-tile-filter` | The filter on the mark inside it: `invert(1)` in light mode by default, `none` for a mark that already contrasts |
| `--banner-bg`, `--banner-fg`, `--nav-bg` | The banner and header ([Configuration](/configuration#topbar)) |
| `--hub-hero-bg`, `--hub-bg` | Hub page backgrounds ([Configuration](/configuration#page-layouts)) |
| `--prose-img-radius`, `--prose-img-border` | Images in page text: corner radius (`12px`) and frame (a 1px line; `none` to drop it) |

```jsonc
"theme": {
  "cssVariables": {
    "light": {
      "--c-paper": "247 246 241",
      "--c-ink": "15 15 14",
      "--c-on-brand": "15 15 14"
    },
    "dark": {
      "--c-paper": "18 18 14",
      "--c-ink": "232 231 224",
      "--c-on-brand": "15 15 14"
    }
  }
}
```

## Fonts

<ParamField path="theme.font.sans / theme.font.mono" type="string">
  Font-family overrides. The font must be system-available or self-loaded (e.g.
  via a `@font-face` in a stylesheet you include). Defaults to Geist.
</ParamField>

```jsonc
"theme": { "font": { "sans": "Inter", "mono": "JetBrains Mono" } }
```

<ParamField path="theme.font.heading" type="string">
  A separate font for page titles and section headings: docs pages, the hub
  hero, landing heroes and the API reference. Unset, headings use the body
  font. Instrument Serif ships with Markline, so a serif heading needs no extra
  loading:
</ParamField>

```jsonc
"theme": { "font": { "heading": "var(--font-instrument-serif), Georgia, serif" } }
```

## Label pill

<ParamField path="topbar.badge" type="string">
  A small bordered pill shown next to the logo — handy for a version or status
  label, e.g. `"docs · v1"` or `"beta"`.
</ParamField>

## Worked example

A complete warm, lime-accented theme that defaults to dark:

```jsonc
{
  "name": "acme",
  "theme": {
    "appearance": "dark",
    "logo": { "icon": "/mark.svg", "text": "acme" },
    "favicon": "/mark.svg",
    "colors": { "primary": "#D7FC50", "primaryDark": "#C2E63D" },
    "cssVariables": {
      "light": { "--c-on-brand": "15 15 14", "--c-paper": "247 246 241", "--c-ink": "15 15 14" },
      "dark":  { "--c-on-brand": "15 15 14", "--c-paper": "18 18 14",  "--c-ink": "232 231 224" }
    }
  },
  "topbar": { "badge": "docs · v1" }
}
```

<Tip>Changing `theme` values takes effect on the next `markline dev` reload —
no rebuild of the framework, ever.</Tip>
